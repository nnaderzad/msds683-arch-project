# web/ — demand dashboard (React 19 + Vite + TypeScript)

The public demo frontend: per-show price/Trends/YouTube history with the
anchor+drift forecast overlaid, plus text-to-SQL Q&A and warehouse browse. It
ships inside the same Cloud Run service as the FastAPI backend
([`../api/README.md`](../api/README.md)) and reads gold live — deploy state and
URL: [`../docs/REPO_STATE.md`](../docs/REPO_STATE.md).

## Run locally

```bash
# backend first (repo root, ADC authed):
conda activate music-demand
uvicorn api.app:app --reload    # http://127.0.0.1:8000

cd web
npm ci
npm run dev                     # Vite dev server; talks to VITE_API_BASE_URL
                                # (default http://127.0.0.1:8000)
npm test                        # vitest (jsdom) — CI runs this on every push
npm run build                   # tsc --noEmit + vite build → dist/
```

## What's what

| Path | Role |
|---|---|
| `src/App.tsx` | hero dropdown + panel layout; only the selected show is fetched live |
| `src/components/DemandSignalsChart.tsx` | the combined price/forecast/signal chart (Recharts) — axis/scale rules in [`CHART_ASSUMPTIONS.md`](CHART_ASSUMPTIONS.md) |
| `src/components/AskPanel.tsx` | text-to-SQL agent UI (`POST /ask`): question box, example chips, guardrail badges, generated SQL, results table |
| `src/components/SearchPanel.tsx` | warehouse browse (`GET /search` + `/genres`): DMA/genre/price/horizon filters |
| `src/data/heroShows.ts` | **GENERATED by `eda/hero_candidates.py` — never edit by hand.** Pre-cached curated hero dropdown (credible forecasts only, no `/shows` fetch); re-run the script to refresh |
| `src/api/client.ts` | typed fetchers for the API endpoints |

Charts cut off at `show_date` and upcoming shows carry a "Today" marker
(UI-side). Missing signals stay visible as nulls — a data-quality feature, not
a bug (see [`CHART_ASSUMPTIONS.md`](CHART_ASSUMPTIONS.md)).
